# API Implementation Plan (Plan 2 of 5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw the product seam ADR 0014 requires, build the domain services that enforce the
role, progress, revocation and conditional-write decisions, and put a documented Hono API in front
of them with a typed client for the two Next.js apps.

**Architecture:** `packages/kernel` keeps only what both products share — roles, `AccessPolicy`,
ids, errors, and the generic ports. `packages/microtask-domain` owns this product's entities, its
storage port and adapter, and its services. `apps/api` is wiring: it resolves a principal from two
credentials, gates every request through `can()`, and serves an OpenAPI document generated from
the same Zod schemas the clients import.

**Tech Stack:** Hono 4.13.7, `@hono/node-server` 2.1.1, `@hono/zod-openapi` 1.6.3, Zod 4.6.1,
Vitest, TypeScript strict.

**Spec:** [`../specs/2026-09-10-monorepo-restructure-design.md`](../specs/2026-09-10-monorepo-restructure-design.md)
**Decisions:** [`../../adr/README.md`](../../adr/README.md)
**Builds on:** [`2026-09-10-foundation.md`](2026-09-10-foundation.md) — complete, 87 tests

> **Read this before starting.** Plan 1 had **twelve** wrong predictions. Eight shared one root
> cause: *a task that runs only `test` ships code that fails `lint` or `typecheck`*. So **run all
> four gates — `lint`, `typecheck`, `test`, `build` — after every task**, regardless of what the
> task's own steps say, and report any gate a step would have missed.
>
> The other recurring lesson: **verify by executing, never by reasoning.** Every wrong prediction
> that got caught was caught by running something. Where a step says "Expected: N tests", report
> the real number rather than adjusting code to match.

## Corrections from executing this plan

Recorded as each group completes, so a later group does not re-learn them.

**A new package whose `package.json` declares `"test": "vitest run"` must land its first test file
in the same commit.** `vitest run` exits **1** on an empty suite — measured: `No test files found,
exiting with code 1` — and no vitest config in this repo sets `passWithNoTests`. Group A hit this
and did not notice: at the end of Task 1, `packages/microtask-domain` had a `test` script and no
test files, and the gate only stayed quiet because turbo skipped that task after an upstream build
failed. The fix is ordering, not `--passWithNoTests`: an empty suite passing silently would hide a
whole package whose tests stopped matching `include`. **This applies to Task 24
(`packages/api-client`), whose manifest this plan does not spell out.** `packages/macroplan-domain`
is the correct pattern for a package with nothing to test yet — it declares no `test` script at all,
and turbo tolerates the missing task.

**`build` and `typecheck` see different files, so a red state reported from `build` alone is
incomplete.** `tsconfig.build.json` excludes `**/*.test.ts`. In Group A, `build` reported 5 errors
and `typecheck` reported 9; `test` then surfaced a third, different failure — a Vite resolution
error rather than a compiler error. Report all three.

**Clearing `dist/` does not give you a cold run — only `--force` does.** `tsc` does not clean
`outDir`, so a moved or deleted module leaves a stale `.d.ts` that a later compile happily
resolves against, and `rm -rf packages/*/dist` fixes *that*. It does **not** defeat the turbo
cache: measured, `rm -rf packages/*/dist && pnpm build` reports `FULL TURBO`, `6 cached, 6 total`,
and restores every `dist/` from the cache. So the obvious recipe reports cache-served numbers as
though they were fresh. This is the third turbo-cache trap in this repo, after a task with no
`outputs` replaying a success log for a bundle it had not written.

The recipe that actually verifies:

```bash
rm -rf packages/*/dist
npx turbo run build typecheck lint test --force   # expect: Cached: 0 cached, N total
```

`pnpm build --force` works too — pnpm passes the flag through to `turbo run`. But
**`pnpm test -- --force` does not**: the explicit `--` forwards the flag to `vitest`, which exits
with ``CACError: Unknown option `--force` `` in every package. Always check the `Cached:` line;
a report that does not quote it has not established anything.

One consequence worth knowing: **`data/` is not a turbo input.** The parity checks in Tasks 4 and
5 read `data/projects`, so a cached `test` result can predate a change to that dataset. Any run
whose result depends on the live data must be forced.

**Local Node is 22.x, and the root `engines.node` was `>=24`.** Nothing enforced it, so every gate
result in Plan 1 and Group A came from an off-spec runtime. The floor is now `>=22.12`, the version
actually verified, so the manifest stops claiming a runtime nobody has run the gates on. ADR 0026
still pins the **image** at `node:24`, which satisfies the floor — but it does mean development and
production run different majors, so anything version-sensitive needs checking on 24 before cutover.

**`no-restricted-imports` options do not merge across flat-config objects — the last matching
block wins outright.** Measured with two config objects both matching `src/**/*.ts`, the first
banning a package by `patterns` and the second banning another by `paths`: only the second was
reported. So a ban placed in the shared base is **silently stripped** from any package that
declares its own `no-restricted-imports` — which `packages/contracts` already does. Any package
needing two bans must merge them into a **single** options object carrying both `paths` and
`patterns`. This is the second time a boundary rule in this repo has been silently inert; the
first was a `files:` glob in the shared config resolving against the wrong directory.

**A control-character class in a regex does not lint, so the URL normaliser is a code-point
predicate.** `no-restricted-syntax`'s sibling `no-control-regex` rejects every spelling of
`/[\u0000-\u0020]/`, and ADR 0027 bans file-level `eslint-disable`, so there is no regex form of
this filter available. `document-guard.ts` filters by code point with named bounds instead. Do not
"simplify" it back to a regex — it will not pass `lint`. Recorded in ADR 0029.

**`assertSafeDocument` as one function measures complexity 11 against a cap of 10.** It is split
into `assertShape` (an assertion function, so no cast is needed) and `assertTree`, leaving the
exported entry point at complexity 1. Group B found this only because it ran `lint`; `test` was
green. That is the ninth instance of this plan's stated root cause.

**The legacy transport cap is 4 MB and nothing in this plan owns it.** `apps/legacy/server.js:97`
rejects a request body over `4000000` bytes with HTTP 413. That is a transport bound, distinct
from the 2 MB document bound in `limits.ts`, and Group B does not carry it forward. **Task 19 owns
it**: the global `bodyLimit` must be at least 4 MB or the API rejects a request production
accepts today, and if it deliberately differs, ADR 0028 should say so.

**Group B's three modules are not in the package barrel.** `progress.ts`, `document-guard.ts` and
`limits.ts` are reachable only inside `packages/microtask-domain`, because no Group B step adds
them to `src/index.ts`. **Group D must add the barrel entries** before anything outside the
package can reach `countTasks`, `assertSafeDocument`, `cleanName` or `LIMITS` — and Group F will
need them from `apps/api`.

**`cleanName` rejects a non-string where legacy coerced one.** Legacy did `String(value ?? '')`,
so a number became `"42"` and an object became `"[object Object]"`; this port throws `Invalid`.
Stricter is right at an untrusted boundary and the Zod contracts reject a non-string before the
domain sees it, but it is a behaviour change on the admin path too, so a test pins it.

**A task-scoped `manage` holder can mint share links it cannot list, and Task 22 must decide what
to do about that.** Measured against the built kernel: `share:read` on a *project* target is
`false` for a task scope, so `projectView` gives such a holder **no `shareLinks` field at all**,
and the per-link filter Group E built is never reached for it. The same holder *is* cleared for
`share:read` on its **own task** target, and ADR 0011 plus the `manage` role explicitly let it
share further. So the authority exists and no route exposes it: `GET /projects/:id/share-links`
gated on `share:read` with a project target will 403 it.

Three ways out, and Task 22 picks one **explicitly** rather than inheriting the 403 by accident:
widen the view's block gate to "this principal may see at least one link here"; add a
task-scoped route gated on `share:read` with a task target; or decide that a task-scoped `manage`
holder genuinely may create-and-revoke-by-token without ever listing, and record why. Group E
pinned the current behaviour with tests, so whichever is chosen, the change is visible.

Related, and corrected here because it was wrong in an earlier instruction: a **project**-scoped
`manage` holder legitimately sees its siblings' tokens, because `share:read` on a project target
clears every link in that project. "A caller sees only its own token" is false and should not be
asserted; the leak tests state per principal exactly which tokens the policy clears.

**`ShareLink.createdBy` holds another link's token, which import can turn into a leak.** ADR 0010
needs it for the revocation cascade, and under well-formed data no principal can see a link whose
`createdBy` names a link it may not see — checked combination by combination. A hand-planted
bundle can break that, since ADR 0017 admits arbitrary files. **Task 19's import validation owns
it**, not a scrub of a field admins need.

**`--reporter=basic` no longer exists in vitest 5** — it fails at startup with `Failed to load
custom Reporter from basic` and prints no summary at all. Use the default reporter.

**Conventions Group D fixed that the plan left open, which Tasks 12–14 must follow.** Each was a
real choice, and picking differently later would leave the manifest holding two contradictory
schemes:

- **Task positions are dense per *folder*, not per project**, and `reorder` takes
  `(product, projectId, folderId, taskIds)` requiring a **strict permutation** of that folder's
  tasks. A partial order is `Invalid` rather than silently dropping the rows a stale client
  omitted. This follows from Task 11's own wording that `move` changes "only `folderId` and
  position", which is only necessary if position is folder-relative.
- **`countTasks` counts one document, but a task's progress spans all its tabs**, so
  `progress.ts` also exports `countTabs(tabs)` and `agreesWith`. Task 12 needs `countTabs` too;
  it must not write a second summation.
- **Correcting the progress cache must not stamp `updatedAt`.** The correcting path writes
  through `store.saveManifest` rather than the service's stamping helper, because otherwise
  merely *opening* a task would reorder the project list by recency.
- **`TaskService.read` is lock-free only on the path where the cache agrees.** Correcting a
  disagreeing cache is a read-modify-write, so it takes the lock and re-reads inside it. The
  consequence is transitive and easy to trip over: **no service may call `TaskService.read`
  from inside its own `lock.run`**, because `QueueLock` is not reentrant and the queue would
  wedge rather than fail. The port's TSDoc says so.

**The Next apps never import `@repo/microtask-domain`.** ADR 0027 restricts `apps/microtask` and
`apps/macroplan` to `contracts`, `api-client` and `ui`, and that boundary is what keeps the
domain barrel safe: `@repo/microtask-domain` re-exports `FsProjectStore` and `paths`, whose
runtime closure reaches `node:path` and — through `@repo/kernel` — `node:crypto`. Neither is
polyfilled in a browser bundle. Two of the barrel's exports
(`emptyDocument`, `NO_PROGRESS`) are **values**, so `import type` does not save a client
component that reaches for either. Plan 4 therefore takes its shapes from `@repo/contracts`
(`z.infer`), which is why that package re-declares them. Group F is where this boundary gets an
ESLint rule, because `apps/api` is the first app to enforce it against.

**An optional, `skipIf`-gated contract case that a new adapter does not implement makes the second
adapter prove less than the first, silently.** This plan's `MemoryProjectStore` sketch read with a
bare `JSON.parse(raw) as T`, which throws on content it cannot decode where `ProjectStore` promises
`null`. The two omissions that hid it fit together: the sketch's harness supplied neither optional
`StoreHarness` capability, so the contract had no way to plant undecodable content, so the one case
that would have caught the bug was skipped rather than failed — and a skipped case reports as a
pass. The shipped harness implements both capabilities and the parse is wrapped. Read a `skipIf`
count as a coverage deficit rather than as a tidy result: the claim that two adapters are
interchangeable is only ever as strong as the cases both of them actually ran.

```ts
import { NO_PROGRESS, type Progress } from './entities/progress.js'

/** How deep a document may nest before the walk stops descending. */
export const MAX_DOCUMENT_DEPTH = 100

interface Frame {
  readonly node: unknown
  readonly depth: number
}

const isNode = (value: unknown): value is Record<string, unknown> =>
  typeof value === 'object' && value !== null

const isChecked = (node: Record<string, unknown>): boolean => {
  const attrs = node['attrs']
  return isNode(attrs) && attrs['checked'] === true
}

/** Counts taskItem nodes in a document. Never stored — always derived (ADR 0007). */
export function countTasks(document: unknown): Progress {
  if (!isNode(document)) return NO_PROGRESS
  let done = 0
  let total = 0
  const stack: Frame[] = [{ node: document, depth: 0 }]
  while (stack.length > 0) {
    const frame = stack.pop()
    if (frame === undefined) break
    const { node, depth } = frame
    if (!isNode(node) || depth > MAX_DOCUMENT_DEPTH) continue
    if (node['type'] === 'taskItem') {
      total += 1
      if (isChecked(node)) done += 1
    }
    const content = node['content']
    if (!Array.isArray(content)) continue
    for (const child of content) stack.push({ node: child, depth: depth + 1 })
  }
  return { done, total }
}
```

```ts
import { Invalid } from '@repo/kernel'
import { MAX_DOCUMENT_DEPTH } from './progress.js'
import type { DocumentJson } from './entities/document.js'

/** The largest a stored document may be, in JSON bytes. */
export const MAX_DOCUMENT_BYTES = 2_000_000

/** Link schemes a document may reference. */
export const SAFE_HREF_SCHEMES = ['http', 'https', 'mailto', 'tel'] as const

const BANNED_KEYS = ['__proto__', 'constructor', 'prototype'] as const

const SCHEME = /^([a-z][a-z0-9+.-]*):/i

const LAST_IGNORED_C0 = 0x20

const FIRST_IGNORED_C1 = 0x7f

const LAST_IGNORED_C1 = 0x9f

const isNode = (value: unknown): value is Record<string, unknown> =>
  typeof value === 'object' && value !== null

const jsonBytes = (value: unknown): number =>
  new TextEncoder().encode(JSON.stringify(value)).length

const ignoredByBrowsers = (char: string): boolean => {
  const code = char.charCodeAt(0)
  return code <= LAST_IGNORED_C0 || (code >= FIRST_IGNORED_C1 && code <= LAST_IGNORED_C1)
}

const asBrowsersSee = (value: string): string =>
  [...value].filter((char) => !ignoredByBrowsers(char)).join('')

function assertHref(value: unknown): void {
  if (typeof value !== 'string') return
  const matched = SCHEME.exec(asBrowsersSee(value))
  if (matched === null) return
  const scheme = (matched[1] ?? '').toLowerCase()
  if (!(SAFE_HREF_SCHEMES as readonly string[]).includes(scheme)) {
    throw new Invalid(`Link scheme "${scheme}" is not allowed`)
  }
}

function assertKeys(node: Record<string, unknown>): void {
  for (const key of BANNED_KEYS) {
    if (Object.hasOwn(node, key)) throw new Invalid(`Key "${key}" is not allowed in a document`)
  }
}

function assertNode(node: Record<string, unknown>): void {
  assertKeys(node)
  assertHref(node['href'])
  assertHref(node['src'])
}

function children(node: Record<string, unknown>): readonly unknown[] {
  const out: unknown[] = []
  for (const value of Object.values(node)) {
    if (Array.isArray(value)) out.push(...value)
    else if (isNode(value)) out.push(value)
  }
  return out
}

function assertShape(document: unknown): asserts document is Record<string, unknown> {
  if (!isNode(document) || document['type'] !== 'doc') throw new Invalid('Not a document')
  const content = document['content']
  if (content !== undefined && !Array.isArray(content)) throw new Invalid('Invalid document content')
  if (jsonBytes(document) > MAX_DOCUMENT_BYTES) throw new Invalid('Document is too large')
}

function assertTree(root: Record<string, unknown>): void {
  const stack: { node: unknown; depth: number }[] = [{ node: root, depth: 0 }]
  while (stack.length > 0) {
    const frame = stack.pop()
    if (frame === undefined) break
    if (!isNode(frame.node)) continue
    if (frame.depth > MAX_DOCUMENT_DEPTH) throw new Invalid('Document is nested too deeply')
    assertNode(frame.node)
    for (const child of children(frame.node)) stack.push({ node: child, depth: frame.depth + 1 })
  }
}

/** Throws Invalid unless a document is safe to store and render (ADR 0029). */
export function assertSafeDocument(document: unknown): asserts document is DocumentJson {
  assertShape(document)
  assertTree(document)
}
```

```ts
import { Invalid } from '@repo/kernel'

/** Every bound this product enforces. Also bounds what a share-link holder can create. */
export const LIMITS = {
  nameLength: 80,
  tabsPerTask: 40,
  tasksPerProject: 500,
  foldersPerProject: 100,
  shareLinksPerProject: 50,
  projectsPerProduct: 500,
} as const

/** A bound that can be exceeded. */
export type LimitKey = keyof typeof LIMITS

/** A bound on a collection. Name length is enforced by truncation, never by `assertWithin`. */
export type CountLimitKey = Exclude<LimitKey, 'nameLength'>

const LABEL: Readonly<Record<LimitKey, string>> = {
  nameLength: 'name length',
  tabsPerTask: 'tabs in this task',
  tasksPerProject: 'tasks in this project',
  foldersPerProject: 'folders in this project',
  shareLinksPerProject: 'share links for this project',
  projectsPerProduct: 'projects',
}

/** Collapses whitespace, trims, and caps a display name. */
export function cleanName(value: unknown, fallback?: string): string {
  if (typeof value !== 'string') {
    if (fallback !== undefined) return fallback
    throw new Invalid('Name is required')
  }
  const collapsed = value.replace(/\s+/g, ' ').trim()
  const cleaned = [...collapsed].slice(0, LIMITS.nameLength).join('').trim()
  if (cleaned.length > 0) return cleaned
  if (fallback !== undefined) return fallback
  throw new Invalid('Name is required')
}

/** Throws Invalid when adding one more would exceed a bound. */
export function assertWithin(key: CountLimitKey, current: number): void {
  if (current >= LIMITS[key]) {
    throw new Invalid(`Too many ${LABEL[key]} — the limit is ${LIMITS[key]}`)
  }
}
```

**behaviour**, which every adapter must share, and the ordering suite pins **durability**, which
only an adapter with a crash window can have at all. Write the order the port documents anyway,
so the two adapters read alike — but do not expect the contract to hold you to it.

```ts
import { Invalid, isProduct, isUlid, type Product } from '@repo/kernel'
import type { ProjectManifest } from '../entities/manifest.js'
import type { ProjectStore } from '../ports/project-store.js'
import type { TaskDocument } from '../entities/task.js'

const key = (product: Product, projectId: string): string => `${product}/${projectId}`

function assertIds(product: Product, projectId: string, taskId?: string): void {
  if (!isProduct(product)) throw new Invalid('Unknown product')
  if (!isUlid(projectId)) throw new Invalid('Project id must be a ULID')
  if (taskId !== undefined && !isUlid(taskId)) throw new Invalid('Task id must be a ULID')
}

export class MemoryProjectStore implements ProjectStore {
  readonly #manifests = new Map<string, string>()
  readonly #tasks = new Map<string, string>()

  clear(): void {
    this.#manifests.clear()
    this.#tasks.clear()
  }

  async listManifests(product: Product): Promise<readonly ProjectManifest[]> {
    if (!isProduct(product)) throw new Invalid('Unknown product')
    const found: ProjectManifest[] = []
    for (const [at, raw] of this.#manifests) {
      if (at.startsWith(`${product}/`)) found.push(JSON.parse(raw) as ProjectManifest)
    }
    return found.sort((a, b) => b.updatedAt.localeCompare(a.updatedAt))
  }

  async readManifest(product: Product, projectId: string): Promise<ProjectManifest | null> {
    assertIds(product, projectId)
    const raw = this.#manifests.get(key(product, projectId))
    return raw === undefined ? null : (JSON.parse(raw) as ProjectManifest)
  }

  async readTask(product: Product, projectId: string, taskId: string): Promise<TaskDocument | null> {
    assertIds(product, projectId, taskId)
    const raw = this.#tasks.get(`${key(product, projectId)}/${taskId}`)
    return raw === undefined ? null : (JSON.parse(raw) as TaskDocument)
  }

  async saveManifest(product: Product, manifest: ProjectManifest): Promise<void> {
    assertIds(product, manifest.id)
    this.#manifests.set(key(product, manifest.id), JSON.stringify(manifest))
  }

  async saveTask(product: Product, manifest: ProjectManifest, task: TaskDocument): Promise<void> {
    assertIds(product, manifest.id, task.id)
    this.#tasks.set(`${key(product, manifest.id)}/${task.id}`, JSON.stringify(task))
    await this.saveManifest(product, manifest)
  }

  async deleteTask(product: Product, manifest: ProjectManifest, taskId: string): Promise<void> {
    assertIds(product, manifest.id, taskId)
    await this.saveManifest(product, manifest)
    this.#tasks.delete(`${key(product, manifest.id)}/${taskId}`)
  }

  async deleteProject(product: Product, projectId: string): Promise<boolean> {
    assertIds(product, projectId)
    const existed = this.#manifests.delete(key(product, projectId))
    const prefix = `${key(product, projectId)}/`
    for (const at of [...this.#tasks.keys()]) {
      if (at.startsWith(prefix)) this.#tasks.delete(at)
    }
    return existed
  }
}
```

## Group D — the services

Every service in this group follows one shape, and it is worth stating once rather than in each
task:

- **Dependencies come through the constructor.** No service reads `process.env` — `n/no-process-env`
  is an ESLint error outside designated config modules (ADR 0027).
- **A service imports nothing from Hono** and never sees an HTTP `Context`. It throws kernel
  `AppError`s (`NotFound`, `Forbidden`, `Invalid`, `Conflict`) and the API maps them to statuses.
- **A service never *gates* on `can()`.** Deciding whether a request may proceed at all is the
  API's job, at a single `authorize()` call site (Task 18); a service that also gated would give
  two places to forget. **Filtering a collection is different and does belong here**: shaping a
  result set per principal has to happen where the items are, or the API would first have to
  receive the very rows ADR 0009 forbids it to see. Such a filter calls `can()` directly rather
  than reimplementing scope containment — `withinTaskScope` and `inScope` are private to
  `policy.ts` on purpose, and a second copy of a security predicate is the worse outcome. This
  affects Task 14 and Group E, and it means Task 23's "one call site" check counts
  `authorize(` — not `can(`. ADR 0009 records the gate/filter split.
- **Every read-modify-write cycle runs inside `lock.run(...)`.** Not a convention: ADR 0006 records
  that atomic replace is not concurrent-safe on Windows, and Task 12 proves what happens without it.
- Files cap at 150 lines, so a service that outgrows one file splits into `<name>-service.ts` plus a
  `<name>-mapper.ts` rather than raising the cap.

```ts
import type { Clock, IdGenerator, Lock } from '@repo/kernel'
import type { ProjectStore } from '../ports/project-store.js'

/** Everything a service needs, supplied by whoever constructs it. */
export interface ServiceContext {
  readonly store: ProjectStore
  readonly lock: Lock
  readonly clock: Clock
  readonly ids: IdGenerator
}

/** A clock frozen at one instant, for deterministic tests. */
export const fixedClock = (at: string): Clock => ({ now: () => at })

const B32 = '0123456789ABCDEFGHJKMNPQRSTVWXYZ'

/** Ids that are distinct, ULID-shaped, and reproducible from a seed. */
export function sequentialIds(seed = 1): IdGenerator {
  let counter = seed
  const next = (prefix: string): string => {
    counter += 1
    const body = String(counter).padStart(6, '0')
    let out = ''
    for (const char of `${prefix}${body}`) out += B32[char.charCodeAt(0) % 32] ?? '0'
    return out.padEnd(26, '0').slice(0, 26)
  }
  return {
    entityId: () => next('E'),
    token: () => `tok_${String(counter++).padStart(16, '0')}`,
  }
}

/** A lock with the same serialising behaviour as production, without the store. */
export function immediateLock(): Lock {
  let chain: Promise<unknown> = Promise.resolve()
  return {
    run<T>(work: () => Promise<T>): Promise<T> {
      const result = chain.then(work, work)
      chain = result.then(
        () => undefined,
        () => undefined,
      )
      return result
    },
  }
}
```

`immediateLock` deliberately has the same `.then(work, work)` shape as `QueueLock`, so a service
test observes production's ordering — including that a rejected task does not poison the chain.

```ts
import { NotFound, type Product } from '@repo/kernel'
import type { ProjectManifest } from '../entities/manifest.js'
import { assertWithin, cleanName } from '../limits.js'
import type { ServiceContext } from './context.js'

/** Creates, reads, renames and removes projects. */
export class ProjectService {
  readonly #ctx: ServiceContext

  /** Creates the service over an injected context. */
  constructor(ctx: ServiceContext) {
    this.#ctx = ctx
  }

  /** Lists every project for a product, newest update first. */
  async list(product: Product): Promise<readonly ProjectManifest[]> {
    return this.#ctx.store.listManifests(product)
  }

  /** Reads one project, or throws NotFound. */
  async read(product: Product, projectId: string): Promise<ProjectManifest> {
    const found = await this.#ctx.store.readManifest(product, projectId)
    if (found === null) throw new NotFound('Project not found')
    return found
  }

  /** Creates an empty project. */
  async create(product: Product, name: string): Promise<ProjectManifest> {
    const cleaned = cleanName(name)
    return this.#ctx.lock.run(async () => {
      const existing = await this.#ctx.store.listManifests(product)
      assertWithin('projectsPerProduct', existing.length)
      const stamp = this.#ctx.clock.now()
      const manifest: ProjectManifest = {
        id: this.#ctx.ids.entityId(),
        name: cleaned,
        folders: [],
        tasks: [],
        shareLinks: [],
        createdAt: stamp,
        updatedAt: stamp,
      }
      await this.#ctx.store.saveManifest(product, manifest)
      return manifest
    })
  }

  /** Renames a project. */
  async rename(product: Product, projectId: string, name: string): Promise<ProjectManifest> {
    const cleaned = cleanName(name)
    return this.#ctx.lock.run(async () => {
      const current = await this.read(product, projectId)
      const next = { ...current, name: cleaned, updatedAt: this.#ctx.clock.now() }
      await this.#ctx.store.saveManifest(product, next)
      return next
    })
  }

  /** Removes a project and everything under it. */
  async remove(product: Product, projectId: string): Promise<void> {
    await this.#ctx.lock.run(async () => {
      const removed = await this.#ctx.store.deleteProject(product, projectId)
      if (!removed) throw new NotFound('Project not found')
    })
  }
}
```

Note `cleanName` runs **outside** the lock: it validates its input and can fail fast without
holding the write queue.

## Group E — principal-shaped views

### Task 15: Views

One route tree serves both an admin and a link holder (ADR 0013), so one handler produces both
representations. A link holder's project must not carry fields only an admin should see — share
links being the obvious one, since an export bundle is a credential dump (ADR 0017).

**Files:**
- Create: `packages/microtask-domain/src/views/{project-view,task-view,share-view}.ts` and tests

- [ ] **Step 1: Write the failing tests, then implement**

Invariants the tests must pin:

- `projectView(manifest, principal)` — an admin gets folders, tasks and **share links**; a
  `view`/`write` link holder gets folders and tasks but **never `shareLinks`**; a `manage` holder
  gets share links **for its own scope only**.
- A **task-scoped** principal's project view contains its own task and nothing else: no sibling
  task entries, no folders, no other names. This is the same rule as search, and it needs its own
  test because it is a different code path.
- `taskView(manifest, task, principal)` — includes the tab documents, and the derived progress.
- `shareView(manifest, link)` — what `GET /shares/current` returns: the link's own role and scope,
  the project name, and what it can reach. It must not include the token of any *other* link.
- Every view is a **pure function** of its inputs: no I/O, no clock, no store. It **does** call
  `can()`, and must. This line previously said "no `can()`" on the grounds that the API has
  already authorized by the time a view runs — true of the *gate*, and irrelevant to what a view
  does. Deciding whether this principal may be shown this share link, this folder, this sibling
  task is a **filter**, and ADR 0009 requires a filter to ask `can()` rather than reimplement
  scope containment. `can()` is itself pure, so the view stays a pure function.

  The pairings, each of which the policy already answers — verified against the built kernel:

  | shown to the caller? | action | target |
  | --- | --- | --- |
  | the share links block | `share:read` | `{ kind: 'project', projectId }` |
  | one particular share link | `share:read` | that **link's own scope** as a target |
  | a folder | `project:read` | `{ kind: 'folder', projectId }` |
  | a task entry | `task:read` | `{ kind: 'task', projectId, taskId }` |

  Deriving the target from *the link being shown* is what makes "a `manage` holder sees share
  links for its own scope only" fall out of the policy instead of being re-expressed: a
  task-scoped `manage` holder asking about a link scoped to a different task is refused by
  `withinTaskScope`, which is the same code the gate runs.

- [ ] **Step 2: Prove the views cannot leak by construction**

Write one test that, for every principal kind (`admin`, project-`view`, project-`manage`,
task-`view`, task-`manage`), serialises the view and asserts the JSON **does not contain** any
token other than the caller's own, and does not contain a sibling task's name for task-scoped
principals.

Assert on the serialised string, not on object properties: a field added later to an inner entity
would slip past a property-by-property assertion and show up in the JSON.

## Group F — `apps/api`

> ### Executed facts this group depends on
>
> Everything below was **measured** against `hono@4.13.7`, `@hono/zod-openapi@1.6.3`,
> `@hono/node-server@2.1.1` and `zod@4.6.1` on 2026-09-10 — not read in documentation. Each is a
> way to write code that looks correct, passes review, and does the wrong thing.
>
> **The four that are outright dangerous:**
>
> 1. **A `.use()` registered *after* the `.route()` or `.openapi()` it should protect never runs,
>    and the request still returns 200.** Measured: middleware registered before →
>    `ran = ["before-route"]`; after → `ran = []`, status 200 either way. This applies to the
>    credential guard and to `bodyLimit` alike (`bodyLimit` after → `200 {"len":500}`; before →
>    `413`). **Register every middleware first, then mount.**
> 2. **The credential middleware is *not* an authorization boundary.** With the guard mounted and no
>    `can()` call in the handler, a share principal scoped to project P1 reading P2 got
>    **`200 {"projectId":"P2"}`**. With the gate: `403`. **Every handler must call `can()` on a
>    target built from the validated params.**
> 3. **`security:` in `createRoute` is documentation only.** A route declaring both bearer schemes
>    answered `200 {"reached":true}` with no credentials at all, and a typo'd scheme name emits with
>    no warning. Enforcement lives in middleware, never in the spec.
> 4. **`c.json(body, '409')` returns HTTP 200.** A string status is silently ignored, with no
>    runtime guard — a client would read a stale write as a successful save. **Numeric statuses
>    only.**
>
> **Structural rules:**
>
> 5. **Every level of the tree must be `OpenAPIHono`.** A plain `Hono` child serves traffic but
>    contributes `doc paths: []` and has no `.openapi()` at all — its routes become permanently
>    undocumentable, with no error at build or run time.
> 6. **Fully populate a child app, then mount it.** Three distinct behaviours, and the silent one
>    is the dangerous one: adding a route to a child after mount → `404` and absent from the
>    document; adding to an app that already served → throws `Can not add a route since the matcher
>    is already built.`; adding to a child after the *parent* served → **no throw, silently
>    unreachable**.
> 7. **Mount each child instance into exactly one parent.** A child binds to whichever parent
>    mounted it first, and that parent's `defaultHook` applies no matter which parent serves.
> 8. **Redeclare every ancestor path parameter in each child route's `request.params`.** A
>    parameter that exists only on the parent's mount path is **not emitted** — a child declaring
>    only `taskId` produced `parameters: [{"name":"taskId"}]` for the path
>    `/v1/projects/{projectId}/tasks/{taskId}`.
> 9. **`route()` takes `:param`; `createRoute()` takes `{param}`.** The brace form in `route()`
>    404s every child route while the document still renders correctly.
>
> **Errors and validation:**
>
> 10. **Never declare `x-api-key` or `Authorization` in `request.headers`.** Required declarations
>     turn a missing credential into a `400` ZodError instead of the contractual `401`, and there is
>     no way to express "either an admin token or a share token" as a header schema. Read them with
>     `c.req.header(...)`, which is case-insensitive and needs no schema.
> 11. **Validation failures do not reach `app.onError`.** They return a raw `400` with the issue
>     array stringified inside `error.message`. Only a `defaultHook` on the **root** constructor can
>     reshape them — and it fires on success too, so it must start `if (result.success) return`.
> 12. **Build error responses with `new Response(...)`, never `c.json(...)`.** Headers set before
>     the throw leak onto the error response: a measured 403 carried
>     `etag` and `x-leak: exists`, revealing that a forbidden resource exists.
> 13. **Throw only `Error` subclasses.** Hono's dispatcher guards with `if (err instanceof Error)`;
>     a thrown string or object bypasses `onError` entirely and produces a bare 500 with no body.
> 14. **A 422 reports only the *first* failing target.** Validators run query → param → header →
>     cookie → json and the hook short-circuits. Include `in: result.target` and expect clients may
>     need several round trips.
> 15. **Do not match on error message strings.** `Malformed JSON in request body` is an
>     `HTTPException` with `.status === 400`, already covered by that branch. Its `.name` reads
>     `"Error"` because `HTTPException` never sets one — which is exactly what makes string matching
>     look necessary. Key on `.status`.
> 16. **A `hook` key on the `createRoute` config is silently ignored** and pollutes the emitted
>     operation. The per-route hook is the **third positional argument** to `app.openapi()`.
>
> **Bodies, streams and the document:**
>
> 17. **There is no default body limit.** A 20 MB POST with no limiter returned
>     `200 {"received":20971520}` over a real socket. Register one global `bodyLimit` as the
>     **loosest** cap and stricter per-route ones — every matching limiter runs and the first
>     rejection wins, so a strict global cannot be loosened per route.
> 18. **`bodyLimit` tests through `app.request()` prove nothing** unless they set a truthful
>     `content-length`. `app.request` sets none, forcing the counting path; production trusts the
>     header. A lying `content-length: 10` on a 500-byte body returned `200`.
> 19. **Never call `c.req.formData()` or `parseBody()` on an upload path.** Memory scales with body
>     size — +371 MB RSS for a 200 MB part, versus +32 MB streaming `c.req.raw.body`.
> 20. **An error thrown inside `stream()` never reaches `onError`** — the client gets HTTP 200 with
>     a truncated body that `fetch().text()` resolves happily. Set a non-200 status *before* calling
>     `stream()`, always pass the third `onError` argument, and declare `Content-Length` (build to a
>     temp file first) so truncation is detectable.
> 21. **Never scrape the live doc route in CI.** When schema generation throws, the route answers
>     `500` with a body that *parses as JSON*, so `curl -s -o openapi.json` exits 0 and overwrites a
>     good spec. Emit from a build script instead; it exits 1 and writes nothing.
> 22. **These schema kinds throw during generation:** `z.set`, `z.map`, `z.custom`, `z.file`,
>     `z.never`, `z.function`, `z.void`, `z.symbol`. Safe: `z.date` → `date-time`, `z.bigint`,
>     `.transform`.
> 23. **Keep `serve()` in one entry file nothing else imports.** An emit script that transitively
>     imports a module calling `serve()` at module scope wrote its file and then never exited.
>     Do not pass `autoCleanupIncoming` — the default `true` is what closes sockets whose body the
>     guard 401'd before reading.
>
> **Verified non-issues:** per-request `c.set()` isolation holds under 60 parallel requests
> (0 mismatches). `getOpenAPI31Document()` does not build the matcher, so registering routes after
> emitting is safe. Doc generation order relative to `app.route()` does not matter.
>
> **Left unverified — budget time:** everything type-level (whether
> `OpenAPIHono<{Variables:{principal}}>` propagates through three mounts, whether
> `c.req.valid('param')` is typed with the parent's params, whether `new Response` is an accepted
> `defaultHook` return type). Also: the offline Swagger UI recipe, external OpenAPI linting, and
> **multi-process concurrency — the promise-chain lock provides no mutual exclusion across
> workers or replicas, so the 19-lost-updates result is what a second replica would produce.**
